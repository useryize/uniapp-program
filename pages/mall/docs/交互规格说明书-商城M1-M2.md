## 2. 全局交互约定（所有页面遵守）

| 约定 | 内容 |
| --- | --- |
| 金额 | 一律 `fen2yuan()` 转元展示；任何页面不计算金额，只展示服务端返回值 |
| 错误 | `catch (e) => uni.showToast({ title: e.msg, icon: 'none' })`，文案来自服务端 |
| 加载 | 首次进入骨架屏或 loading；分页触底加载；下拉刷新后 `uni.stopPullDownRefresh()` |
| 空态 | 每页必须有空态视图 + 引导按钮（如空购物车 → 去逛逛） |
| 防重 | 提交类按钮点击后立即置 loading，防止重复提交（PRD §7.4 幂等的前端配合项） |
| 封面 | `goods.cover` 有值显示图片，否则用 `color` 色块 + 标题首字（mock 占位，接接口自动切图） |
| 路由 | 页面间 `uni.navigateTo`；tab 类跳转如需 switchTab 由你调整 pages.json 后同步改 |

## 5. 各页面交互规格

### P1 商品详情 `pages/mall/detail/index?id={goodsId}`

**数据**：`goodsApi.detail({ id })`，onLoad 取参。

**区块**（自上而下）：
1. 图集轮播：mock 阶段单张色块（`color` + 标题首字），swiper 结构预留多图
2. 价格区：`minPrice`（红）/ `originPrice`（划线）/ `已售 sales`
3. SKU 选择弹层：规格行（`skuList`）、数量步进器（1 ~ 当前 SKU `stock`）
4. 商品描述：`description` 文本段
5. 底部操作栏（固定）：`加入购物车` + `立即购买`

**交互规则**：
- 切换 SKU → 价格与库存显示实时联动（数据全部来自详情接口，前端不算价）
- `stock === 0` 的 SKU 规格按钮**置灰禁用**（PRD §①：售罄保留展示不可下单）
- 全部 SKU 售罄 → 两个按钮置灰 + 文案「暂时售罄」
- 加购：`cartApi.add({ goodsId, skuId, quantity })` → 成功 toast「已加入购物车」；失败 toast 展示服务端文案（超库存 40001 等）
- 立即购买：携带 `{ skuId, quantity }` 跳结算页（单品直购，即 PRD §15 备选裁剪路径）

**验收**：
- [ ] SKU 切换价格联动；售罄禁用
- [ ] 加购超库存提示服务端文案
- [ ] 步进器不超 `stock`

### P2 购物车 `pages/mall/cart/index`

**数据**：`cartApi.list()` → `{ list, checkedCount, checkedAmount }`，onShow 刷新（从结算页返回时数量可能变）。

**区块**：
1. 商品项：勾选框 / 色块封面 / 标题+规格 / 实时单价 / 数量步进 / 删除
2. 失效商品区：`invalid === true` 置灰底部，仅提供「清空失效」
3. 底部结算栏（固定）：全选框 + `已选 N 件 合计 ¥xx` + `去结算`

**交互规则**：
- 改量：`updateQty` 失败（超库存）→ toast 并**回滚显示**到服务端返回值
- 删除：`uni.showModal` 二次确认 → `remove({ ids })`
- 勾选/全选：`setChecked` / `checkAll`，合计金额**只用服务端返回的 `checkedAmount`**
- 去结算：无选中禁用；有选中携带选中项 `ids` 跳结算页
- 空态：空购物车插画位 + 「去逛逛」按钮 → 返回首页

**验收**：勾选实时更新合计（服务端口径）；删除有确认；空态完整。

### P3 订单确认（结算） `pages/mall/confirm/index?ids={cartIds}` 或 `?skuId=&quantity=`

两种入口：购物车去结算（ids）、详情页立即购买（skuId+quantity）。

**数据**：
- 商品明细：入口为 ids 时调 `cartApi.list()` 前端按 ids 过滤选中项展示（金额用服务端返回值）；入口为直购时调 `goodsApi.detail` 组装展示（**仅展示**，提交时仍传 skuId+quantity 由服务端计价）
- 地址：`addressApi.list()` 取 `isDefault` 项；无地址显示「+ 新增收货地址」占位（地址编辑页 P8 可放次优先级）

**区块**：地址卡 / 商品清单 / 金额明细（商品合计 + 运费规则文案「满 ¥99 包邮」）/ 订单备注输入（≤200 字）/ 底部「提交订单」（显示提交后应付款项不可提前算 → 按钮文案「提交订单」）

**交互规则**：
- 提交：`orderApi.create({ items: [{ skuId, quantity }], addressId, remark })` → 成功跳支付结果页 `?orderNo=xx&from=create`
- 提交中按钮 loading 防重（§7.4）
- 失败（库存不足/下架/未选地址）：toast 服务端文案，停留本页

**验收**：[ ] 篡改金额无入口（页面无金额输入）[ ] 重复点击不产生两单 [ ] 未选地址被服务端 40004 拦截并提示。

### P4 支付结果 `pages/mall/pay/result?orderNo=&from=create`

**状态机（页面内三态）**：
1. **待支付**（from=create 初始）：展示订单号 + 应付金额 + 主按钮「模拟支付」+ 次按钮「取消」
2. **支付成功**：成功 icon + 金额 + 「查看订单」→ 订单详情
3. **支付异常**：展示服务端错误文案

**交互规则**：
- 「模拟支付」调 `orderApi.mockPay({ orderNo })` → 成功切状态 2
- 40006（超时竞态）→ 切状态 3，文案固定：「订单已超时关闭，支付金额将自动原路退回」（对应 PRD §7.3 规则 3，真实环境由服务端自动退款）
- 「取消」→ 跳订单列表（订单仍在 15 分钟待付款内，可回来继续支付）
- 真实环境替换点：按钮「模拟支付」→ `uni.requestPayment`（代码位置留 `// TODO 真实支付` 注释）

### P5 订单列表 `pages/mall/order/list?status=`

**数据**：`orderApi.list({ status, page, pageSize })`，tab 五个：全部 / 待付款 / 待发货 / 待收货 / 已完成。

**每项**：状态文案（`orderStatusText`）、首个商品快照缩略 + 「共 N 件」、实付金额、按状态渲染操作按钮：

| 状态 | 按钮 |
| --- | --- |
| UNPAID | 去支付（→ 支付结果页）/ 取消订单（showModal 确认 → `cancel`） |
| PAID / SHIPPED | 查看详情 |
| FINISHED / CANCELED | 查看详情 |

**待补 mock**：确认收货按钮需 `order.confirm`（见 §6）。

**验收**：tab 切换重置分页；触底加载；空态按 tab 区分文案。

### P6 订单详情 `pages/mall/order/detail?orderNo=`

**数据**：`orderApi.detail({ orderNo })`。

**区块**：状态 + 时间轴（createTime → payTime → shipTime → finishTime，仅展示已发生的）/ 地址快照（`maskedPhone` 脱敏）/ 商品快照列表（**快照字段** titleSnapshot/specSnapshot/price）/ 金额明细（totalAmount + freight + discountAmount + payAmount）/ 订单号（uni.setClipboardData 复制）/ 备注。

操作按钮同 P5 规则。

### P7 搜索 `pages/mall/search/index`

- 输入防抖 300ms → `goodsApi.list({ keyword, page })`，结果复用首页商品卡组件样式
- 搜索历史：本地 `uni.setStorageSync('mall_search_history')`，上限 10 条，可清空
- 空结果：「没有找到相关商品」+ 清空筛选按钮
