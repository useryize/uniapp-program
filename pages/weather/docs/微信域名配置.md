# 微信小程序合法域名配置（完整指引）

> 本文档对应 `pages/weather/` 天气模块所需的全部域名配置。
> 首次配置约需 10 分钟，配置后需等待 5–15 分钟平台缓存刷新才全局生效。

---

## 一、配置入口（直达地址）

### 主入口

```
https://mp.weixin.qq.com/
```

用**管理员**微信扫码登录（只有管理员或拥有「开发管理」权限的成员能修改域名配置，
运营者/普通开发者身份看不到入口）。

### 直达链接（登录态下有效）

| 页面 | 地址 |
|------|------|
| 开发设置 / 服务器域名 | `https://mp.weixin.qq.com/wxopen/devprofile` |
| 开发管理总览 | `https://mp.weixin.qq.com/cgi-bin/dev/index?t=dev_index` |

> `devprofile` 链接带 `token` 参数，该参数由登录会话生成，直接复制别人分享的链接会跳登录页。
> 稳妥做法是登录后走菜单：**开发 → 开发管理 → 开发设置**，页面往下拉到底就是「服务器域名」。

### 菜单路径

```
小程序后台
 └─ 开发
     └─ 开发管理
         └─ 开发设置   ← 标签页
             └─ 服务器域名  ← 页面最底部区块
                 ├─ request 合法域名      ← 主要配置这里
                 ├─ socket 合法域名
                 ├─ uploadFile 合法域名
                 └─ downloadFile 合法域名
```

点「修改」进入编辑态，会要求**管理员再次扫码确认**。

## 二、要填什么（照抄即可）

### request 合法域名

```
api.open-meteo.com
air-quality-api.open-meteo.com
api.rainviewer.com
```

### downloadFile 合法域名

```
tilecache.rainviewer.com
```

> **为什么瓦片要单独配 downloadFile？**
> 雷达瓦片是 `<image>` 组件加载的网络图片（`pages/weather/explore/radar.vue`），
> 底层走 `wx.downloadFile` 而非 `wx.request`，**不走 request 白名单**。
> 开发者工具里勾了「不校验合法域名」能显示，真机预览和正式版会静默失败
> （`image` 的 `error` 回调甚至不触发），这是最容易踩的坑。

### 不用配的

| 类型 | 本项目是否需要 | 原因 |
|------|---------------|------|
| socket 合法域名 | ❌ 不需要 | 代码中无 `connectSocket` / `ws://` / `wss://` |
| uploadFile 合法域名 | ❌ 不需要 | 无文件上传 |
| 业务域名（web-view） | ❌ 不需要 | 无 `web-view` 组件 |
| DNS 预解析域名 | 可选 | 同一页面可加 5 个，填 `api.open-meteo.com` 可减少首屏 DNS 等待 |

### 填写格式要求

| 项 | 要求 | ✅ 正确 | ❌ 错误 |
|----|------|---------|--------|
| 协议头 | **必须写 `https://`** | `https://api.open-meteo.com` | `api.open-meteo.com` |
| 路径 | 不能带 | `https://api.open-meteo.com` | `https://api.open-meteo.com/v1/forecast` |
| 端口 | 不能带（默认 443 也不能显式写） | `https://api.open-meteo.com` | `https://api.open-meteo.com:443` |
| IP / localhost | 不支持 | — | `https://127.0.0.1` |
| 父域名 | 不支持，必须填子域名 | `air-quality-api.open-meteo.com` | `open-meteo.com` |

> 注：`api.open-meteo.com` 与 `air-quality-api.open-meteo.com` 是两个独立子域名，
> 官方明确「不支持配置父域名」，所以**必须分开添加，不能只填 `open-meteo.com`**。

## 三、配置前的三项自检（已实测通过）

配置前先确认接口本身合规，避免配完了还是被拒：

```bash
# 1. 连通性 —— 四个域名全部 200
curl -s -o /dev/null -w "%{http_code}\n" "https://api.open-meteo.com/v1/forecast?latitude=30.27&longitude=120.15&current=temperature_2m"
curl -s -o /dev/null -w "%{http_code}\n" "https://air-quality-api.open-meteo.com/v1/air-quality?latitude=30.27&longitude=120.15&current=pm2_5"
curl -s -o /dev/null -w "%{http_code}\n" "https://api.rainviewer.com/public/weather-maps.json"
curl -s -o /dev/null -w "%{http_code}\n" "https://tilecache.rainviewer.com/v2/radar/36d40d6ddd45/256/6/54/26/4/1_1.png"

# 2. TLS 版本 —— 必须 >= 1.2（微信硬性要求）
echo | openssl s_client -connect api.open-meteo.com:443 -servername api.open-meteo.com 2>/dev/null | grep -i "Protocol"

# 3. 证书链完整性
echo | openssl s_client -connect tilecache.rainviewer.com:443 -servername tilecache.rainviewer.com -showcerts 2>/dev/null | grep -c "BEGIN CERTIFICATE"
```

**本项目实测结果（2026-10-28）**：

| 域名 | HTTP | TLS |
|------|------|-----|
| `api.open-meteo.com` | 200 | TLSv1.3 ✅ |
| `air-quality-api.open-meteo.com` | 200 | TLSv1.3 ✅ |
| `api.rainviewer.com` | 200 | TLSv1.3 ✅ |
| `tilecache.rainviewer.com` | 200 | TLSv1.3 ✅ |

四个域名均满足微信的 HTTPS + TLS 1.2 要求，证书链完整。

## 四、ICP 备案问题（境内主体必读）

官方文档写明「域名必须经过 ICP 备案」，但这条规则的实际口径是：

- **境内主体 + 境内服务器** → 必须已备案（工信部备案号），否则后台提交不通过
- **境外域名**（服务器在境外，如 `open-meteo.com`、`rainviewer.com`）→ **不强制要求备案**

微信平台官方答复原文：

> 「境外注册域名不强制要求域名备案，但需确保域名解析正常且服务可用。
> 若小程序主要面向国内用户，建议优先选择国内服务器或 CDN 以提升访问速度。」

> 「配置的服务器域名能否通过系统审核，以页面提示为准。」

### 潜在风险与对策

| 风险 | 表现 | 对策 |
|------|------|------|
| 境外域名未备案 | 后台提交时可能提示备案校验失败 | 配置时若被拒 → 见下方「备案兜底方案」 |
| 审核不通过 | 小程序提审时因接口域名问题被驳回 | 准备说明：数据来源为公开气象 API，非经营性内容 |
| 国内访问延迟 | 首屏数据加载慢（境外服务器） | 已在 `api/http.js` 做 Storage 缓存（实况 30 分钟 / 雷达清单 3 分钟），命中缓存时秒开 |

### 备案兜底方案（配置被拒时启用）

自建一个国内已备案的 HTTPS 反向代理，把四个接口转发到境外源站：

```
用户小程序  →  https://你的域名.com/wx/weather/forecast   （已备案，配置这一个）
                →  https://api.open-meteo.com/v1/forecast
```

改动很小，只需在 `pages/weather/api/http.js` 里加一个 `BASE_URL` 前缀常量：

```js
// pages/weather/api/http.js
const PROXY = ''   // 例：'https://your-domain.com/wx'
const withProxy = (url) => (PROXY ? PROXY + url.replace(/^https?:\/\/[^/]+/, '') : url)
```

改完后 `request 合法域名` 只需填你自己那一个已备案域名。
（Nginx 反代需注意 `Host` 头透传，以及 RainViewer 的 `path` 是短生命周期哈希、
**不能缓存代理层**——`api.rainviewer.com` 那一路建议直连或设 `no-store`。）

## 五、开发阶段跳过校验（临时）

微信开发者工具：**详情 → 本地设置 → 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**

> ⚠️ 这个开关**只对开发者工具和手机调试模式生效，正式版一律校验**。
> 它还有一个副作用：**连 `<image>` 网络图片也会绕过校验**，
> 导致「工具里图正常、真机白屏」的现象——真机调试时尤其容易误判。
>
> 官方建议：**配置完成后关掉这个开关再测一遍**，确保正式环境可用。

## 六、配置后的验证步骤

1. **等待生效**：保存后 5–15 分钟平台缓存刷新，期间可能仍报 `url not in domain list`
2. **开发者工具重新编译**：点「编译」重新拉取配置，否则本地仍用旧缓存
3. **关闭「不校验合法域名」**，切到**真机预览**（不是开发工具）
4. 逐页验证：

| 页面 | 验证点 | 预期 |
|------|--------|------|
| 01 首页 | 大温度 / 24h 横滑 / 7 日预报 | 正常渲染 |
| 06 空气质量 | AQI 环 + 6 项污染物 | 正常渲染 |
| 08 降水雷达 | 瓦片图层 | **瓦片能显示**（这条最容易挂） |
| — | DevTools Network 面板 | 无 `url not in domain list` |

## 七、报错速查

| 报错 | 根因 | 解决 |
|------|------|------|
| `url not in domain list` | 域名没配 / 配错类目 / 没重新编译 | 检查 request 类目；重新编译 |
| `downloadFile:fail url not in domain list` | 雷达瓦片域名没进 downloadFile | 补 `tilecache.rainviewer.com` |
| `不在以下 request 合法域名列表中` | 同上 | 同上 |
| `SSL handshake failed` | 证书链不全 / TLS < 1.2 | `openssl s_client -showcerts` 查链 |
| 图片空白但无 error 日志 | `<image>` 网络图未配 downloadFile | 补 downloadFile 域名 |
| 开发工具正常、真机失败 | 「不校验合法域名」只在工具生效 | 关掉开关重测 |
