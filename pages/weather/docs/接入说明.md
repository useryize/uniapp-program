# 天气模块接入说明

## 一、微信小程序配置（必做，否则请求会被拦截）

微信小程序对 `wx.request` 有**合法域名白名单**限制，未配置会直接报
`url not in domain list`。需要在**微信公众平台**配置：

> 微信公众平台 → 开发 → 开发管理 → 开发设置 → 服务器域名 → request 合法域名

需添加以下域名（各计一个配额，共 3 个）：

| 域名 | 用途 | 必要性 |
|------|------|--------|
| `api.open-meteo.com` | 天气实况 / 预报 / 空气质量 | ✅ 必需 |
| `air-quality-api.open-meteo.com` | 空气质量（AQI 与污染物） | ✅ 必需 |
| `tilecache.rainviewer.com` | 降水雷达瓦片图片 | 建议（08 页用） |
| `api.rainviewer.com` | 雷达帧清单 | 建议（08 页用） |

> ⚠️ `api.rainviewer.com` 与 `tilecache.rainviewer.com` 是两个不同域名，需分别添加。

**图片域名**：雷达瓦片走 `<image>` 加载，还需在「downloadFile 合法域名」中一并配置
`tilecache.rainviewer.com`。

开发阶段如需临时跳过校验，可在微信开发者工具中勾选：
**详情 → 本地设置 → 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**。

---

## 二、H5 / App 端

无需额外配置。`uni.request` 在 H5 端走浏览器 fetch，仅受 CORS 限制——
Open-Meteo 与 RainViewer 均已开启 CORS。

---

## 三、运行方式

```bash
# 安装依赖
npm install

# H5 开发
npm run dev:h5

# H5 构建 → dist/build/h5
npm run build:h5

# 微信小程序构建 → dist/build/mp-weixin（用微信开发者工具导入该目录）
npm run build:mp-weixin

# 微信小程序开发（watch 模式）
npm run dev:mp-weixin
```

> 首次运行若报 `Could not resolve "./App"`，说明缺少 `vite.config.js`。
> 本项目已附带该文件，其中把 `UNI_INPUT_DIR` 指向项目根目录（因为本项目是
> **根目录结构**而非 uni-app 默认的 `src/` 布局）。

## 五、关键实现说明

### 数据流
```
页面 → api/index.js → api/weather.js（适配器）→ Open-Meteo
                        ↓
              WMO 码映射 + 单位换算 + 指数自算
                        ↓
              设计稿约定的 JSON 结构 → 页面直接渲染
```

页面**不直接请求接口**，也**不计算任何派生值**（风级、AQI 分级、生活指数全部在适配层完成）。

### 缓存策略
| 数据 | TTL | 位置 |
|------|-----|------|
| 天气预报 | 30 分钟 | Storage `wx_fc_{adcode}_fc` |
| 空气质量 | 30 分钟 | Storage `wx_fc_{adcode}_air` |
| 雷达清单 | 3 分钟 | Storage `wx_radar_manifest` |

雷达的 `path` 是短生命周期哈希，**必须每 3 分钟重拉清单**，不能长期缓存。

### 生活指数
Open-Meteo 免费层不提供生活指数，8 项均由 `utils/indices.js` 按气象阈值推导。
推导规则见该文件注释。**若后续要换成官方口径**，只需替换 `calcIndices` 的实现，
页面无需改动。

### 城市库
`data/cities.js` 由构建期脚本生成（DataV 行政区划中心点 + pinyin-pro 拼音），
共 367 个地级市及直辖市。**已内联进产物**，运行时零网络请求。

城市库存为 `.js` 而非 `.json`：小程序端的 JSON import 与 Node ESM 行为不一致，
统一用 JS 模块可同时兼容两端。

### 图标
`static/weather/icons/` 下 30 个 PNG：
- 11 个天气图标常规版（晴/多云/阴/雨/小雨/雪/雾/霾/夜/雷暴/冻雨）
- 11 个深底变体（`-light` 后缀，用于首页深蓝 Hero 区）
- 8 个生活指数专属图标（`idx-` 前缀）

设计成 PNG 而非内联 SVG，是因为小程序 `<image>` 对 SVG 支持不稳定。

## 六、已知限制

1. **商业授权**：Open-Meteo 与 RainViewer 的免费层**均不允许商业使用**。
   若小程序要上线运营并有商业行为，需改用和风天气 / 彩云天气（免费额度更紧，
   但提供国内城市、预警、雷达等），或购买 Open-Meteo 商业授权。
   接入点集中在 `api/weather.js` 与 `api/radar.js`，替换成本可控。

2. **雷达无预报帧**：实测 RainViewer 的 `nowcast` 数组为空，08 页时间轴
   目前只能回放实况回波，页面已做降级提示文案。

3. **生活指数非官方口径**：由气象要素推导，与商业 App 文案不完全一致。

4. **拖拽排序**：管理页的手柄拖动基于 touch 坐标与固定行高估算，
   在 iOS 端 `scroll-view` 内可能有轻微偏差，可按需调 `ROW_HEIGHT` 常量。

5. **霾判定**：Open-Meteo 无霾指数，用「高湿 + 低 PM + 弱风」组合近似，
   与气象部门的霾标准不完全等价。
