## 二、Open-Meteo（主数据源，免费无 Key）

### 为什么是它
- **无需注册、无需 API Key、无需信用卡**
- 一次请求可同时返回 current / hourly / daily / 空气质量
- 覆盖 16 天预报（设计稿 05 页要 15 天 ✓）
- 数据源为各国气象模式（ECMWF / NOAA / CMA 等），非地面站插值

### 额度
| 维度 | 免费层 |
|------|--------|
| 每分钟 | 600 次 |
| 每小时 | 5,000 次 |
| 每天 | 10,000 次 |
| 每月 | 300,000 次 |
| 商业使用 | ❌ 不允许（需付费档） |

> ⚠️ **商业授权是硬门槛**。如果这个小程序要上线运营并有商业行为，Open-Meteo 免费层不可用，必须换和风/彩云或购买授权。这是选型的第一决策点。

### 实测可用接口

**① 天气预报**（01/04/05 页）
```
GET https://api.open-meteo.com/v1/forecast
  ?latitude=30.2741&longitude=120.1551
  &current=temperature_2m,relative_humidity_2m,apparent_temperature,
          precipitation,weather_code,surface_pressure,wind_speed_10m,
          wind_direction_10m,is_day
  &hourly=temperature_2m,apparent_temperature,precipitation_probability,
          weather_code,uv_index
  &daily=weather_code,temperature_2m_max,temperature_2m_min,sunrise,sunset,
         uv_index_max,precipitation_sum
  &timezone=Asia/Shanghai&forecast_days=16
```
实测返回 `HTTP 200`，17.4 KB，字段与设计稿一一对应：

| 设计稿字段 | Open-Meteo 字段 | 单位 |
|-----------|---------------|------|
| 23° 当前温度 | `current.temperature_2m` | °C |
| 体感 25° | `current.apparent_temperature` | °C |
| 湿度 65% | `current.relative_humidity_2m` | % |
| 东南风 3级 | `current.wind_speed_10m` + `wind_direction_10m` | km/h · ° |
| 气压 1013hPa | `current.surface_pressure` | hPa |
| 降水概率 10% | `hourly.precipitation_probability` | % |
| 最高 26° / 最低 18° | `daily.temperature_2m_max/min` | °C |
| 日出 05:42 / 日落 18:36 | `daily.sunrise` / `sunset` | ISO8601 |
| 空气质量 AQI | 空气质量 API `current.us_aqi` | USAQI |

> 注意：`wind_speed_10m` 默认单位是 **km/h**，设计稿显示"3级"需要换算风力等级（km/h ÷ 3.6 = m/s，再查蒲福风级表）。

**② 空气质量**（06 页）
```
GET https://air-quality-api.open-meteo.com/v1/air-quality
  ?latitude=30.2741&longitude=120.1551
  &current=pm10,pm2_5,carbon_monoxide,nitrogen_dioxide,sulphur_dioxide,ozone,us_aqi
  &timezone=Asia/Shanghai
```
实测 `HTTP 200`，返回 6 项污染物，正好对上设计稿 06 页的 PM2.5 / PM10 / O₃ / NO₂ / SO₂ / CO 六行。
`us_aqi` 是美国 AQI 标准（0–500），中国标准（0–500，但分级点不同）需自行换算，或改用 `european_aqi`。

**③ 地理编码**（城市搜索）
```
GET https://geocoding-api.open-meteo.com/v1/search?name=杭州&count=10&language=zh
```
⚠️ **实测有歧义**：搜"杭州"返回 2 条，第一个是浙江省杭州市 ✅，第二个是**四川省甘孜藏族自治州**（同名地点）❌。

**结论：不要用 Open-Meteo 的地理编码做中文城市搜索**，改用本地城市库（见 §三）。

## 三、城市库（02/03 页，免费）

### 推荐：`china-area-data`（npm，MIT）
```
https://cdn.jsdelivr.net/npm/china-area-data@5.0.1/data.json
```
实测 `HTTP 200`，116 KB，结构为三级联动（省 → 市 → 区县），行政区划码即国标 GB/T 2260：

```json
{
  "86":    { "110000": "北京市", "330000": "浙江省", ... },
  "330000": { "330100": "杭州市", "330200": "宁波市", ... },
  "330100": { "330106": "西湖区", "330108": "滨江区", ... }
}
```

**用法**：打包进 `static/` 目录，本地建索引（名称 → 坐标）。坐标可一次性用 Open-Meteo 批量反查并缓存为静态 JSON，运行时零请求。

### 备选：高德 Web 服务 API
`https://restapi.amap.com/v3/config/district` 实测可达（HTTP 200），但需申请 Key，且返回的是**区县级**全量列表（数据量大），适合做服务端预处理，不适合前端直查。

> ⚠️ 中国大陆坐标有 **GCJ-02 偏移**。Open-Meteo 用 WGS84。若用高德/腾讯的坐标查 Open-Meteo，会有 **300–600m 偏移**。方案：用 Open-Meteo 自己的地理编码拿 WGS84 坐标，或对 GCJ-02 做逆偏移。

## 四、07 生活指数（8 项）— 唯一需要决策的点

### 现状
- **Open-Meteo 没有生活指数**（实测确认：只有 uv_index / precipitation_probability / wind 这类原始变量）
- **彩云天气有**：免费版给 **4 项**（穿衣 / 洗车 / 感冒 / 紫外线），逐日数据里返回
- **和风天气有**：生活指数接口需确认免费档是否开放

### 三个方案

**方案 A：全部自算（0 成本，推荐）**
用已有原始变量按行业阈值推导，8 项全都能算：

| 指数 | 计算依据（全部来自已验证字段） |
|------|-------------------------------|
| 穿衣 | `apparent_temperature` 分档 → 6 档文案 |
| 紫外线 | `uv_index_max` → 弱/中等/强/很强/极强 |
| 洗车 | `precipitation_sum` + `precipitation_probability_max` → 适宜/不宜 |
| 运动 | `apparent_temperature` + `wind_speed_10m_max` + `precipitation_probability_max` → 5 档 |
| 感冒 | 昼夜温差（`temperature_2m_max/min` 之差）+ 风力 → 少发/易发 |
| 晾晒 | 降水量 + `uv_index_max` + 风速 → 3 档 |
| 过敏 | 干燥度（湿度 + 温度）→ 低/中/高（简化版，非花粉数据） |
| 出行 | 能见度代理 + 降水 + 风 → 良好/一般/较差 |

优点：**零依赖、零额度消耗、规则透明可调**
缺点：过敏指数不够医学严谨；与商业 App 的文案不会完全一致

**方案 B：混用彩云（补 4 项）**
Open-Meteo 做主数据 + 彩云免费版补穿衣/洗车/感冒/紫外线。
代价：多一个 Token、多一次请求、免费版只有 3 天逐日预报（15 天要加 `dailysteps=15` 参数且可能超额度）

**方案 C：和风天气全量**
一个 Key 解决全部，但免费额度（约 1000 次/天）紧张，且需确认各接口在免费档的开放情况。

### 我的建议
**方案 A 起步**。8 项指数里有 6 项是纯温湿度/降水的确定性推导，做出来可信度高；等生活指数做完了再评估是否值得为"过敏"接彩云。

## 五、08 降水雷达（RainViewer，免费无 Key）

### 实测结果
```
GET https://api.rainviewer.com/public/weather-maps.json   → HTTP 200
```
返回结构：
```json
{
  "version": "2.0",
  "generated": 1793154620,
  "host": "https://tilecache.rainviewer.com",
  "radar": {
    "past": [
      {"time": 1793147400, "path": "/v2/radar/bf4110a09f43"},
      {"time": 1793148000, "path": "/v2/radar/42c7f8211aaf"},
      ...共 13 帧
    ],
    "nowcast": []
  }
}
```

**帧时间戳新鲜度实测**：`generated` = 10:30:20，最新 `past` 帧 = 09:50，间隔 10 分钟 → 与设计稿 08 页时间轴刻度（现在 / +30分 / +1小时 / +2小时 / +3小时）**完全对得上**。

**瓦片实测**：
```
https://tilecache.rainviewer.com/v2/radar/36d40d6ddd45/256/6/54/26/4/1_1.png
→ HTTP 200, image/png, 334 bytes
```
标准 XYZ 瓦片格式，可直接喂给 `<image>` + `map` 组件。

### 瓦片 URL 规则
```
{host}{path}/{size}/{z}/{x}/{y}/{color}/{options}.png
```
| 参数 | 取值 |
|------|------|
| `size` | 256 / 512 |
| `z` | 最大 7 |
| `color` | 配色方案 ID（4 = 通用） |
| `options` | `{smooth}_{snow}`，如 `1_1` = 平滑 + 显示雪 |

### ⚠️ 三个坑
1. **path 是短生命周期的**（示例中 `36d40d6ddd45` 这种哈希），**必须每 3–5 分钟重新拉一次清单**，不能缓存 path 本身
2. **必须署名**："Weather data by RainViewer" + 链接回 rainviewer.com（免费条款强制）
3. **仅限个人/教育/小型社区使用**，无 SLA，不保证可用性；商业用途需单独谈

### 地图底图（免费）
- 瓦片本身只画雷达回波，**不含底图**。底图需另接：
  - 高德/腾讯 JS API（国内，需 Key，有配额）
  - OpenStreetMap 瓦片（免费但商用有限制）
  - 天地图（免费，需 Key，个人可申请）

设计稿 08 页目前用的是**示意图底图**，落地时替换为真实瓦片即可，布局不用改。

## 七、落地建议

### 架构
```
┌─────────────────────────────────────────┐
│  小程序前端                                │
│  ├─ 城市库 city.json（静态，内置）        │
│  ├─ 缓存层（storage，TTL 见下）           │
│  └─ 适配层 weatherAdapter.js（统一字段）  │
└──────────────┬──────────────────────────┘
               │  统一出口：吐设计稿的 JSON 结构
┌──────────────▼──────────────────────────┐
│  适配层做三件事：                         │
│  ① WMO weather_code → 中文文案 + 9个图标  │
│  ② 单位换算（km/h→风级、μg/m³、AQI标准）  │
│  ③ 生活指数自算（温湿度/降水/UV 推导）    │
└──────────────┬──────────────────────────┘
               │
   ┌───────────┼───────────┬──────────────┐
   ▼           ▼           ▼              ▼
Open-Meteo  RainViewer  城市库       wttr.in
(天气/AQI)   (雷达)      (本地)      (降级兜底)
```

### 缓存策略（关键，直接决定额度够不够）
| 数据 | 缓存 TTL | 理由 |
|------|---------|------|
| 实况天气 | 10 分钟 | 设计稿 01 页刷新频率 |
| 逐小时 | 30 分钟 | 小时级数据 |
| 逐日 / 15天 | 1–3 小时 | 日级数据变化慢 |
| 空气质量 | 30 分钟 | 实测 AQI 变化平缓 |
| 雷达清单 | **3 分钟** | path 短生命周期，必须频繁重拉 |
| 雷达瓦片 | 10 分钟（按帧+瓦片坐标） | 瓦片本身可缓存 |

按「单城市单次会话 = 4 次请求」估算，**1 万次/天的免费额度约可支撑 2500 用户/天的完整浏览**。缓存做足的话个人项目完全够用。

### 天气码映射表（对应设计稿 9 个图标）
Open-Meteo 返回 WMO code，需映射到设计稿的图标库：

| WMO | 中文 | 设计稿图标 |
|-----|------|-----------|
| 0 / 1 | 晴 / 大部晴朗 | 晴 |
| 2 | 多云 | 多云 |
| 3 | 阴 | 阴 |
| 45 / 48 | 雾 / 雾凇 | 雾 |
| 51 / 53 / 55 | 毛雨系列 | 小雨 |
| 61 / 63 / 65 | 小雨 / 中雨 / 大雨 | 小雨 / 雨 / 雨 |
| 66 / 67 | 冻雨 | 雨 |
| 71 / 73 / 75 / 77 | 雪系列 | 雪 |
| 80 / 81 / 82 | 阵雨系列 | 雨 |
| 85 / 86 | 阵雪 | 雪 |
| 95 / 96 / 99 | 雷暴系列 | 雨（需加闪电标记） |
| `is_day=0` | 夜间 | 夜 |

> 设计稿图标库已有 9 个：晴 / 多云 / 阴 / 雨 / 小雨 / 雪 / 雾 / 霾 / 夜 —— 覆盖全部 WMO 码，但**雷暴与冻雨需要复用「雨」图标并加角标**，这一点建议在设计稿里补一版。

### 已知缺口
1. **霾**（设计稿图标有）—— Open-Meteo 无霾指数，需用能见度 + 湿度 + PM 组合判定
2. **雷暴 / 冻雨** —— 需复用雨图标，建议设计侧加角标变体
3. **过敏指数** —— 简化为干燥度代理，或接彩云
4. **降水雷达 3 小时预报帧** —— RainViewer 的 `nowcast` 实测为空数组，需优雅降级（只播回波动画 + 提示"暂无预报帧"）
