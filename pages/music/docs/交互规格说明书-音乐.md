## 1. 调研前置结论（产品边界的来源）

以下均为真实请求实测，不是文档抄录。这些结论直接决定了产品**不做什么**。

### 1.1 接口能力清单

| 能力 | 可用 | 接口 | 实测备注 |
| --- | --- | --- | --- |
| 榜单·热门歌曲 | ✅ | `GET /v1/tracks/trending?time=week\|month\|allTime` | 三档时间 + 可选曲风交叉筛选 |
| 曲风筛选 | ✅ | `?genre=Electronic` | 30+ 曲风可用；**`genre=All` 返回 0 条，需省略该参数** |
| 专题歌单 | ✅ | `GET /v1/playlists/trending?time=` | 返回歌单名/封面/曲目数/作者 |
| 歌单曲目 | ✅ | `GET /v1/playlists/{id}/tracks` | 实测 15–20 首，全部 `is_streamable` |
| 搜索·歌曲 | ✅ | `GET /v1/tracks/search?query=` | 支持中文 |
| 搜索·歌单/艺人 | ✅ | `/v1/playlists/search`、`/v1/users/search` | — |
| 艺人主页 | ✅ | `GET /v1/users/{id}` + `/v1/users/{id}/tracks` | — |
| 音频直链 | ✅ | `GET /v1/tracks/{id}/stream` | **302 → 307 → CDN，签名地址短期有效** |
| 评论 | ✅ | `GET /v1/tracks/{id}/comments` | **含 `track_timestamp_s` 播放时间戳** |
| 歌词 | ❌ | — | 404，无此接口 |
| 相似/相关推荐 | ❌ | — | 404，需自行拼装 |
| 用户系统 | ⚠️ | OAuth PKCE | 只读接口无需登录；收藏/关注需授权 |

### 1.2 四个硬约束

**① 没有歌词接口。** 不做歌词页，不做逐句滚动歌词。

**② 没有相似推荐接口。** 不做「猜你喜欢」这种黑盒推荐。改成**可解释推荐**：每张推荐位必须说明理由（「同曲风」「同艺人」「同期上榜」）。

**③ 中文曲库是用户搬运的盗版。** 搜「周杰伦」返回 5 条，全部来自同一个账号「Jay 周杰伦」。曲库表面丰富，实际随时下架。**不做华语流行分类，不做歌手排行榜。**

**④ `api.audius.co` 无 ICP 备案。** 微信小程序 request 合法域名会做实时备案校验，未备案直接 `url not in domain list`。**小程序端必须走自建中转域名；H5 端可直连。**

### 1.3 性能基线（决定缓存与骨架屏策略）

| 指标 | 实测值 | 设计要求 |
| --- | --- | --- |
| API 响应 | 1.6–3.9s（10/10 成功，均值 2.5s） | **必须骨架屏**，不能白屏等待 |
| 音频首字节 | 4.8s | 点击播放 → 立即进「缓冲中」态，不得静默 |
| 音频码率 | ~48KB/s（audio/mpeg，206 分段） | 支持分段加载，可拖动 seek |
| 稳定性 | 10 次连续请求 100% 成功 | 无需重试风暴，单次重试即可 |

## 2. 产品定位与主张

**一句话定位**：给独立音乐一个「能听见的理由」。

### 2.1 三个差异化支点

| 支点 | 说明 | 竞品对比 |
| --- | --- | --- |
| **曲风是一等公民** | 曲风不是二级分类 tab，是首页主结构。首屏横向滑动的曲风胶囊直接驱动内容流 | 网易云按「推荐/歌单」组织，曲风藏在筛选里 |
| **评论挂时间轴** | 播放时评论按 `track_timestamp_s` 在封面区飘过，听到那一秒就看见那句话 | 网易云评论在列表里，与播放进度脱节 |
| **推荐必须给理由** | 每个推荐位标注来源（同曲风 / 同艺人 / 本周上榜第 N） | 「猜你喜欢」不可解释 |

### 2.2 明确不做

歌词页 · K 歌 · MV · 关注/粉丝社交 · 华语流行分类 · 付费/会员 · 评论区发帖（只读）

### 2.3 视觉骨架（待高保真确认）

> 与商城的 Y2K 酸性黄、壁纸的轻白、天气的深蓝都刻意区隔：**深夜黑胶**质感。

| 项 | 值 |
| --- | --- |
| 画布底 | `#0A0A0C`（近黑，微冷） |
| 卡片面 | `#151519` / 悬浮态 `#1D1D23` |
| 主色（强调） | 荧光青 `#00E0B8` |
| 次强调 | 橙红 `#FF5A36`（仅用于「正在播放」波形与倒计时） |
| 文字四级 | `#FFFFFF` / `#A8A8B3` / `#6E6E7A` / `#42424C` |
| 播放页背景 | 取当前曲目封面主色，双层径向渐变 + 40px 高斯模糊 |
| 字体 | Inter（数字/英文）+ Noto Sans SC（中文），**不引入第三套字体** |
| 圆角 | 封面 16px / 卡片 14px / 胶囊 999px（曲风标签、按钮） |

## 5. 全局交互约定

### 5.1 播放器单例（硬约束）

整个应用**只有一个音频实例**，状态存在一个模块级 `reactive` 对象里：

```
pages/music/store/player.js
  ├─ state: { queue, index, current, status, progress, duration, mode, buffered }
  ├─ actions: playTrack / playList / toggle / next / prev / seek / setMode
  └─ 平台分支：小程序 backgroundAudioManager / H5 innerAudioContext
```

**页面禁止自建音频实例**。所有页面通过 `player.state` 读、`player.actions` 写。

### 5.2 音频上下文选型（关键技术决策）

| 端 | 用哪个 | 原因 |
| --- | --- | --- |
| 小程序 | `uni.getBackgroundAudioManager()` | **只有它支持退到后台/锁屏继续播放** |
| H5 | `uni.createInnerAudioContext()` | 后台播放由浏览器控制，无需 BAM |

**BAM 的三个坑（必须写进实现）**：

1. `src` 赋值即自动播放 → 「暂停后继续」只能调 `play()`，**不能重设 src**
2. `title` / `singer` / `coverImgUrl` **必填**，否则锁屏与通知栏是空白
3. 同一时刻只能有一个 BAM 实例，切歌必须先 `stop()` 再赋新 `src`

**manifest.json 需新增**（当前缺失）：

```json
"mp-weixin": {
  "requiredBackgroundModes": ["audio"]
}
```

### 5.3 缓存策略

| 内容 | Key | TTL | 失效方式 |
| --- | --- | --- | --- |
| 榜单（每 time×genre 组合） | `m_chart_{time}_{genre}` | 10 min | 下拉刷新强制 |
| 歌单详情 | `m_pl_{id}` | 30 min | 下拉刷新强制 |
| 艺人信息 | `m_artist_{id}` | 60 min | — |
| 搜索结果 | `m_q_{type}_{query}` | 5 min | 换关键词 |
| **每日推荐列表** | `m_daily_{YYYY-MM-DD}` | **到次日 0 点** | 跨天自动失效（不可手动刷新，见 §8.2） |
| Banner 编排 | `m_banner_{YYYY-MM-DD}` | 到次日 0 点 | 跨天自动失效 |
| 用户口味画像 | `m_profile` | 永久 | 每次播完/收藏后增量更新 |
| **音频直链** | **不缓存** | — | 每次播放前现取（签名短期有效） |
| 收藏 / 最近播放 | `m_favs` / `m_recent` | 永久 | 用户操作 |

### 5.4 加载与反馈

| 场景 | 表现 |
| --- | --- |
| 首屏 | 骨架屏（不用 loading 遮罩），至少 3 个卡片占位 |
| 分页 | 触底加载，底部 40px 转圈；无更多时显示「已经到底了」 |
| 下拉刷新 | home / chart / playlist 支持，结束后 `uni.stopPullDownRefresh()` |
| 点播放 | **立即**置 `status='loading'` 并把 mini-bar 进度条变灰，不得静默等待 4.8 秒 |
| 全局错误 | `uni.showToast({ title: e.msg, icon: 'none' })`，文案来自 api 层 |

### 5.5 空态与降级

| 场景 | 空态文案 | 引导 |
| --- | --- | --- |
| 搜索无结果 | 没找到「{query}」相关音乐 | 「换个关键词」+ 推荐 3 个热门曲风 |
| 收藏为空 | 还没有收藏任何曲目 | 「去发现」→ home |
| 最近播放为空 | 听过的音乐会出现在这里 | 「去发现」→ home |
| 歌单无曲目 | 这张歌单是空的 | 「返回」 |
| 网络失败 | 网络不给力，数据没拿到 | 「重试」按钮（复用上次缓存） |

### 5.6 微信胶囊安全区（硬约束）

小程序右上角**始终**悬浮微信胶囊按钮（返回/更多/关闭），它是原生层，无法被页面内容覆盖，也不会被 `clipsContent` 裁掉。

| 项 | 值（375 宽基准） |
| --- | --- |
| 胶囊位置 | 右边缘内 7px 起，宽 87，高 32 |
| 垂直位置 | `statusBarHeight`（44）+ 4 = **48 起，到 80** |
| 危险区 | `x ∈ [278, 375]`、`y ∈ [48, 80]` |

**规则（所有页面必须遵守）**

1. 顶栏（状态栏下方那一行）的 **`paddingRight` 一律 100**，把右侧 100px 整块让给胶囊。
2. 危险区内**不放任何可点击元素**：搜索、更多、筛选、换一批等入口全部内移到 `x ≤ 275`。
3. 需要右对齐的元素（更多按钮、换一批、更新时间）在 flex 里用 **`spacer + fill_container` 顶开**，不要用 `SPACE_BETWEEN` 硬推——否则会顶到胶囊底下。
4. 状态栏（44px）这一行照常绘制时间与系统图标；真机上该行由系统渲染，设计稿保留是为了视觉完整。
5. 页面标题靠左（`paddingLeft` 16），不受影响；**居中标题**在有小程序胶囊时会视觉偏右，故本项目标题一律左对齐。
6. **实现时不要写死 100**。设计稿的 100 是 375 基准值，真机应用
   `wx.getMenuButtonBoundingClientRect()` 取胶囊实际 `left`，再算 `paddingRight = 屏宽 - 胶囊.left + 8`；
   状态栏高度同理用 `wx.getWindowInfo().statusBarHeight`（安卓不同机型 24~48 不等，写死 44 会错位）。

### 5.7 全局顶部 TabBar

一级页面共用同一条顶部 TabBar，用于在「发现 / 榜单 / 我的」之间切换。

| 项 | 规格 |
| --- | --- |
| 高度 | 48 |
| 左侧内边距 | 16 |
| 项间距 | 22 |
| 标签字号 | 16（选中 Noto Sans SC SemiBold `#FFFFFF`，未选中 Regular `#6E6E7A`） |
| 选中指示 | 文字下方 3px 主色短线，宽 18，圆角 2，与文字间距 4 |
| 右侧 | 留白 100（胶囊安全区）；首页在该留白左侧放 30px 圆形搜索按钮 |

**生效范围**

| 页面 | 是否有 TabBar |
| --- | --- |
| 发现 `home` / 榜单 `chart` / 我的音乐 `library` | ✅ 一级页，显示 |
| 每日推荐 / 播放器 / 歌单详情 / 歌单广场 / 搜索 / 艺人 | ❌ 二级页，用返回箭头，不显示 |

**为什么二级页不放**：TabBar 的语义是「切换一级目的地」，二级页已有明确的来路（返回箭头）。两者同时出现，用户会分不清「返回」和「切 tab」哪个才是退出。底部 mini-bar 已经承担了跨页的播放状态锚点，顶部再叠一层全局导航会过载。

## 6. 播放器内核规格（本模块最核心）

### 6.1 状态机

```
                    ┌──────────┐
        ┌───────────│   idle   │◀─────────── 队列清空 / stop
        │           └────┬─────┘
        │        playTrack│
        │           ┌────▼─────┐   404/403   ┌────────┐
        │           │ loading  ├────────────▶│ error  │
        │           └────┬─────┘             └───┬────┘
        │      onCanplay │                       │ 自动 next()
        │           ┌────▼─────┐                 │
        │      ┌────│ playing  │◀────┐           │
        │      │    └────┬─────┘     │           │
        │ pause│         │onEnded    │resume     │
        │      │    ┌────▼─────┐     │           │
        │      └───▶│  paused  ├─────┘           │
        │           └────┬─────┘                 │
        │                │ 最后一首 && 非循环     │
        └────────────────┴───────────────────────┘
```

**状态枚举**：`idle | loading | playing | paused | error`
UI 只认这五个值，不额外引入 `buffering`（loading 兼任）。

### 6.2 播放模式（三态循环）

| 模式 | 图标 | `next()` 行为 | `onEnded` 行为 |
| --- | --- | --- | --- |
| `list` 列表循环 | 循环箭头 | index+1，越界回 0 | 同 next |
| `single` 单曲循环 | 箭头带 1 | index+1 | **重播当前曲**（seek 0 + play） |
| `shuffle` 随机 | 交叉箭头 | 从 queue 随机取（不与当前重复） | 同 next |

默认 `list`。模式持久化到 storage `m_mode`。

### 6.3 进度与 seek

| 规则 | 说明 |
| --- | --- |
| 进度源 | `onTimeUpdate`（约 250ms/次），**本地只读**，不做插值动画补帧 |
| 拖拽 | `touchstart` → 置 `dragging=true`，暂停进度回写；`touchmove` 只更新 UI；`touchend` → `seek(target)` 并恢复回写 |
| 拖拽中的显示 | 进度条上方浮出时间气泡 `01:23 / 03:45`，松手后 800ms 淡出 |
| seek 边界 | 目标值 clamp 到 `[0, duration-1]`；`duration` 未知（0）时禁用拖拽 |
| 缓冲态 | `buffered` 字段画进度条第二层浅色，不足 2% 不绘制 |

### 6.4 切歌与队列

| 规则 | 说明 |
| --- | --- |
| 入队 | `playList(list, startIndex)` 覆盖整个队列；`playTrack(t)` 单曲入队并播放 |
| 顺序 | 队列顺序 = 用户点击那一刻的列表顺序（不重排） |
| 去重 | 同一次 `playList` 内按 trackId 去重，保留首次出现 |
| 上限 | 队列最多 200 首，超出截断并在末尾 toast「队列已满」 |
| prev 行为 | 当前进度 > 3 秒 → 回到 0；≤ 3 秒 → 上一首（**这是行业惯例，必须做**） |
| 切歌过渡 | 保留旧封面 150ms 再做 200ms 淡入，避免白闪 |

### 6.5 后台播放与锁屏

| 端 | 要求 |
| --- | --- |
| 小程序 | `requiredBackgroundModes: ["audio"]`；每首歌必须传 `title` / `singer` / `coverImgUrl` |
| 锁屏控制 | BAM 自带上一首/下一首回调 → 接到 player 的 `prev/next` |
| 来电打断 | `onInterruptionBegin` → 置 `paused`；`onInterruptionEnd` → **不自动续播**（避免打扰） |
| 拔出耳机 | `onHeadphonesDisconnected` → 置 `paused`（不做自动播放） |

### 6.6 音频错误映射

| 错误 | 判定 | 处理 |
| --- | --- | --- |
| 曲目已下架 | `stream` 返回 404 | toast「该曲目已下架」→ **自动 next()** → 队列连续失败 3 次则停止并提示 |
| 需授权/门禁 | `stream` 返回 403 或 `is_stream_gated=true` | 直接跳过，**不 toast**（静默跳过） |
| 网络超时 | `errCode=1` 或 8 秒无 canplay | 重试 1 次；仍失败 → toast「网络不稳定」并暂停 |
| 解码失败 | `errCode=4` | toast「音频格式不支持」→ 跳过 |

> 设计含义：**用户不应该看见报错弹窗**。坏曲目静默跳过，只在连续失败时提示一次。

## 7. 评论时间轴（核心差异化）

### 7.1 数据准备

播放某曲时，`GET /tracks/{id}/comments?limit=50` 一次性拉取，按 `track_timestamp_s` 升序排序，构建索引 `[{t: 8, text, user}, {t: 23, ...}]`。

**注意**：部分评论 `track_timestamp_s` 为空 → 归入「无时间戳」桶，只在评论列表里展示，不上弹幕层。

### 7.2 呈现规则

| 规则 | 值 |
| --- | --- |
| 位置 | 封面区下沿往上 1/3 处，从右向左飘 |
| 触发 | `progress >= comment.t - 1.5s` 时入场（提前一点，让用户听到那句话时正好看到） |
| 时长 | 6 秒飘过；同屏最多 3 条，第 4 条排队 |
| 样式 | 14px / 半透明黑底胶囊 / 白字 / 圆角 999px |
| 开关 | 播放页右上角「弹」按钮，关闭后整个弹幕层隐藏，**状态持久化** |
| 密度控制 | 同一首歌弹幕总数上限 30 条（超出按时间均匀采样） |

### 7.3 点击行为

点弹幕 → 暂停播放 + 打开评论面板并定位到该条。这样「看到一句话」能立刻「看懂上下文」。

### 7.4 降级

评论接口失败或为 0 条 → 弹幕层不显示，不占位、不报错。播放页右上角「弹」按钮置灰。

### 8.2 每日推荐 `pages/music/daily/index`

**先说清楚它为什么做得出真东西。** Web 端没有个性化推荐接口，但「每日推荐」的实质不是算法多聪明，而是三件事：**① 每天不一样 ② 同一天不变 ③ 听过的会消失**。这三件事只需本地数据即可达成，不需要服务端。

#### 8.2.1 算法（确定性抽样，不是随机）

**输入**

| 项 | 来源 | 说明 |
| --- | --- | --- |
| `profile.genreCounts` | 本地统计 | 每播完一首该曲风 +1，权重衰减 7 天 |
| `profile.recentTrackIds` | 最近播放 | 最近 7 天，用于排除 |
| `profile.favTrackIds` | 收藏 | 用于排除 |
| `dateKey` | `YYYY-MM-DD` | 决定当天快照 |
| `deviceSeed` | 首次启动随机串 | 同一天不同设备结果不同，避免所有人看到同一份 |

**步骤**

```
1  候选池  ← top3 曲风 × (week + month) 各 20 首  +  全局 week 20 首  → 去重
2  过滤    ← 剔除 recentTrackIds / favTrackIds / is_stream_gated
3  配额    ← 按 genreCounts 权重分配 30 个位置
             top1 40%(12) · top2 25%(8) · top3 15%(4) · 全局榜单 20%(6)
4  洗牌    ← seed = hash(dateKey + deviceSeed)
             每个曲风桶内用 seed 做 Fisher-Yates，取前 N
5  兜底    ← 不足 30 首则补全局 week 榜；仍不足则显示实际数量，不凑数
```

**稳定性保证**：`seed` 只依赖「日期 + 设备」，**与请求时刻无关**。所以同一天内无论进入多少次、下拉多少次，结果完全一致。这是可验证的信任感。

#### 8.2.2 理由生成（按优先级取第一条命中）

| 条件 | 文案 |
| --- | --- |
| 曲风 === `profile.top1` | `因为你常听 {曲风}` |
| 艺人出现在最近播放里 | `你听过 {艺人} 的 {N} 首` |
| 本周榜单排名 ≤ 50 | `本周新上榜` |
| 其余 | `今天值得一听` |

理由不是装饰。它是这套无服务端推荐的**可解释性出口**，也是和「猜你喜欢」黑盒的根本区别。

#### 8.2.3 页面区块

1. 顶部大日期区：`11 / 01`（42px 数字）+ 「每日推荐」+ 「根据你的收听生成 · 30 首」
2. `播放全部` 主色胶囊 + 副文案「同一天内不会变，明天 0 点更新」
3. 曲目列表 30 条（曲目行 + 右侧理由标签 11px 描边胶囊）
4. 底部安全区 88px

#### 8.2.4 交互规则

| 操作 | 行为 |
| --- | --- |
| 下拉刷新 | **不刷新列表**，顶部 toast「今天的推荐明天更新」——刻意的，为了守住「同一天不变」 |
| 点单曲 | 整 30 首入队，从该首开始 |
| 点「播放全部」 | 从第 1 首开始，整列入队 |
| 新用户进入 | 顶部提示「听几首后推荐会更准」，列表走全局 week 榜均衡分配 |
| 加载中 | 骨架屏 5 条 |

#### 8.2.5 验收

- [ ] 同一天内退出重进，列表顺序与内容**完全一致**
- [ ] 当日中途收藏某首，当日列表不变；次日该首被剔除
- [ ] 跨天重新生成，前 3 首至少 2 首与昨日不同

| 切曲风 | 带 `genre` 参数重取；`全部` **不传该参数**（传 `All` 返回空，见 §1.1）；切换后滚动回顶部 |
| 点「换一批」 | `time` 在 `week → month → allTime` 之间轮换，复用同一批 DOM，列表 200ms 淡入；**不跳页、不清滚动位置以外的状态** |
| 下拉刷新 | 清 TTL 缓存 + 重取当前 time/genre 组合 |
| 空结果 | 空态「这个曲风还没有专题」+ 按钮「看全部」（把曲风切回「全部」） |

**为什么不做无限滚动**
`playlists/trending` 在单一 `time` 维度下的可翻页条目很有限，实测 `offset` 越往后越容易返回重复或空数组。**用「换一批」换时间维度，比做无限滚动体验更实**：用户永远能拿到新内容，且不会滚到一片空白。

**验收**
- [ ] 「全部」不传 `genre`，切换任意曲风都有数据
- [ ] 换一批后卡片内容确实变化（不是同一批换了顺序）
- [ ] 首页「查看全部」→ 本页，返回后首页滚动位置不丢
- [ ] 网格在 375 宽下不出现换行错位（166×2 + 11 = 343）

## 9. 数据层设计

### 9.1 目录结构（对齐 mall / weather 约定）

```
pages/music/
├─ api/
│  ├─ http.js           # uni.request 封装，超时 8s，统一 {code,msg} 错误对象
│  ├─ source/
│  │  └─ audius.js      # Audius 适配器（含小程序中转 BASE 的条件编译）
│  ├─ normalizer.js     # 原始响应 → 内部统一模型
│  └─ index.js          # 页面唯一取数口 + TTL 缓存
├─ store/
│  └─ player.js         # 播放器单例（reactive），双平台音频上下文
├─ utils/
│  ├─ format.js         # 时长 / 播放量 / 日期格式化
│  ├─ profile.js        # 本地画像：曲风计分（7 天半衰）、最近播放、收藏
│  └─ daily.js          # 每日推荐确定性抽样 + 理由生成
├─ components/          # 10 个：status-bar / nav / tab-bar / mini-bar /
│                       #        track-row / genre-chips / banner /
│                       #        daily-entry / progress / skeleton
├─ data/
│  └─ genres.js         # 曲风常量表 + 时间维度 + 中文映射
├─ styles/
│  └─ tokens.scss       # 色板 / 字阶 / 圆角 / 间距
├─ home/  daily/  player/  playlist/  playlists/  chart/
├─ search/  artist/  library/
└─ docs/  design/

```

> **实现已完成，构建通过**（`npm run build:h5`）。两处与设计稿的差异说明：
> 1. `source/` 只有 `audius.js` 一个文件，小程序中转用 `// #ifdef MP-WEIXIN` 条件编译切换 `BASE`，没有单独的 `proxy.js`——两者字段完全一致，拆文件反而要维护两份相同逻辑。
> 2. 音频直链不预取 302 目标，直接把 `.../stream` 交给播放器跟随跳转（实测 `backgroundAudioManager` 与 `innerAudioContext` 都能跟）。

⚠️ **小程序端跑之前必须改这一行**：`api/source/audius.js` 里 `MP-WEIXIN` 分支的 `https://music-proxy.example.com/v1` 要换成你自己的备案域名，否则 `request` 合法域名校验直接拦。

### 9.2 统一内部模型

适配器必须把两种来源归一化成同一形状，页面只认这个：

```js
// Track
{ id, title, artistId, artistName, artistAvatar, cover, coverSmall,
  duration, playCount, genre, streamable, isGated }

// Playlist
{ id, name, cover, trackCount, ownerName, ownerId }

// Artist
{ id, name, avatar, followerCount, trackCount }
```

### 9.3 适配器切换

```js
// api/index.js
const BASE = __MP_WEIXIN__ ? PROXY_BASE : 'https://api.audius.co/v1'
```

页面对 `BASE` 无感知。**所有差异（字段名、分页参数、错误码）都收敛在 `source/` 里。**

### 9.4 曲风常量

实测可用的 30 个曲风取其中 12 个进首页/榜单横滑条（其余在「更多曲风」展开）：

```
Lo-Fi · Electronic · Hip-Hop/Rap · Ambient · House · Jazz
Classical · Drum & Bass · Rock · Techno · R&B/Soul · Pop
```

⚠️ 传 `genre=All` 返回空数组，**「全部」选项必须省略参数**。

## 10. 异常与降级清单

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| E1 | 小程序端未配置中转域名 | 全局拦截 → 展示「音频服务未就绪」引导页（**不要静默空白**） |
| E2 | 曲目已下架 | 静默跳过，连续 3 次失败停止 |
| E3 | 接口超时（8s） | 重试 1 次；仍失败 → 空态 + 重试按钮 + 残留缓存 |
| E4 | 评论接口失败 | 弹幕层隐藏，「弹」按钮置灰，不报错 |
| E5 | 收藏项已失效 | 置灰 + 「移除」，不自动删 |
| E6 | 队列为空时点 mini-bar | 回 home |
| E7 | 后台播放被系统杀死 | 重进 app 时恢复 `lastTrack` 到 paused 态（不自动播） |
| E8 | Banner 封面加载失败 | 退化为纯色渐变底（取封面主色）+ 文案照常显示，**不留灰块** |
| E9 | 每日推荐候选不足 30 首 | 显示实际条数，标题同步改数量，不重复填充凑数 |
| E10 | 用户清空本地存储（画像丢失） | 按新用户逻辑重算，不报错、不锁死 |

### 11.3 上线前阻塞项（需外部条件）

| 阻塞 | 影响 | 解法 |
| --- | --- | --- |
| **域名备案** | 小程序端无法请求 Audius | 自建中转 + 备案域名（7–20 工作日） |
| **文娱-音乐类目资质** | 小程序审核可能驳回 | 《网络文化经营许可证》或《信息网络传播视听节目许可证》 |

> **结论**：本模块当前定位为**可演示的高保真作品**。H5 端可完整跑通；小程序端需完成上表前两项才能上线。
