# 音乐模块 · 接口与域名清单

> 对应 `pages/music/`。清单来自 2026-11-01 真实请求实测。
> 想直接配就抄第一节；想知道为什么这么配，看后面。

---

## 一、照抄区：填进小程序后台

### request 合法域名（必填，1 条）

```
https://api.audius.co
```

覆盖全部数据接口：`trending` / `search` / `playlist` / `user` / `comments` / `stream` 入口。

### downloadFile 合法域名

**不填。** 原因见 §四。

### 可选（先不填，播放无声再加）

```
https://creatornode.audius.co
```

音频 `stream` 接口的 302 目标域名。音频播放走 `innerAudioContext` / `backgroundAudioManager`，不校验 request 白名单，多数情况不需要配。

### 填写格式（踩过的坑）

| 项 | 要求 | ✅ | ❌ |
| --- | --- | --- | --- |
| 协议头 | 必须带 | `https://api.audius.co` | `api.audius.co` |
| 路径 | 不能带 | `https://api.audius.co` | `https://api.audius.co/v1` |
| 端口 | 不能显式写（443 也不行） | `https://api.audius.co` | `https://api.audius.co:443` |
| IP / localhost | 不支持 | — | `https://127.0.0.1` |
| 父域名通配 | 不支持 | `https://api.audius.co` | `https://*.audius.co` |

入口：`https://mp.weixin.qq.com/` → 开发 → 开发管理 → 开发设置 → 服务器域名 → 修改（需管理员扫码二次确认，保存后 5–15 分钟生效）。

| 接口 | 域名 | 结论 |

## 三、音频流的完整跳转链（实测）

```
GET https://api.audius.co/v1/tracks/{id}/stream?app_name=xxx
  → 302  https://creatornode.audius.co/tracks/cidstream/{cid}?signature=...
  → 307  同域名，补 skip_play_count 参数
  → 200  audio/mpeg
```

两个关键点：

1. **签名带 timestamp**，短期失效 → 音频直链**不能缓存、不能落库**，每次播放前现取。代码里 `fetchStreamUrl` 故意没套 TTL 缓存，就是这个原因。
2. **播放器直接吃 `.../stream` 这个入口即可**，让它自己跟随 302/307。`backgroundAudioManager` 和 `innerAudioContext` 实测都能跟。

## 四、封面图：6 个域名，配不完

实测拉 5 首热门曲目，`artwork` 落在 **6 个完全不同**的域名上：

```
audius-content-3.figment.io
audius-creator-12.theblueprint.xyz
cn0.mainnet.audiusindex.org
v.monophonic.digital
val013.open-audio-validator.com
val017.open-audio-validator.com
```

这是 Audius 去中心化架构的直接后果：曲目存在哪个节点，封面图就在哪个域名下。**每首歌都可能不同，节点域名还会变。**

结论：

- 想靠 downloadFile 白名单覆盖，等于追一条一直在变的列表 → **不可行**
- 现状：开发工具勾了「不校验合法域名」能看封面；**真机可能白封面**
- 这是已知限制，不是配置漏了

要彻底解决只有两条路：走中转代理图片（§五 方案 B），或接受真机封面缺失。

## 五、两种上线路径

### 方案 A：直配源站（省事，先试这个）

就是第一节那条 `https://api.audius.co`。

| 成功率因素 | 说明 |
| --- | --- |
| 域名备案 | 微信对**境外域名**的口径是「不强制要求备案，但需确保域名解析正常且服务可用」，所以有机会通过；最终以后台提交页面的提示为准 |
| 封面图 | 真机大概率白封面（无解，除非走代理） |
| 访问速度 | 跨境请求，实测均值 2.5s，首屏靠骨架屏 + TTL 缓存兜住 |

**代价**：封面图在真机上可能不显示，列表看起来是空的。

### 方案 B：自建中转（唯一能彻底解决的）

需要：境内域名 + 境内服务器 + ICP 备案（7–20 工作日）+ HTTPS 证书。

中转只暴露 1 个域名，路径分流：

| 中转路径 | 转发到 |
| --- | --- |
| `/v1/audius/*` | `https://api.audius.co/v1/*` |
| `/v1/img?u={urlencode(原图)}` | 封面图原地址（**解决 §四**） |
| `/v1/stream/:id` | 音频入口，**透传 302 不跟随** |

> ⚠️ 音频不要在中转层跟随 302。跟随意味着服务器先把整首歌下载到内存再吐给小程序，一首 3 分钟的歌几十 MB，并发几首就崩。
> Nginx 的 `proxy_pass` 默认原样返回 302，符合要求；用代码写反代时注意 `redirect: 'manual'`。

**代码改动点（仅两处）**

```js
// 1. pages/music/api/source/audius.js
//    MP-WEIXIN 分支的 BASE 改成中转地址
BASE = 'https://api.yourdomain.com/v1/audius'

// 2. pages/music/api/index.js
//    封面图统一包一层代理
const IMG_PROXY = 'https://api.yourdomain.com/v1/img?u='
```

后台只需配 `https://api.yourdomain.com` 这一条。

## 六、备案口径（别被误读）

微信官方原文：

> 「境外注册域名不强制要求域名备案，但需确保域名解析正常且服务可用。
> 若小程序主要面向国内用户，建议优先选择国内服务器或 CDN 以提升访问速度。」

这句话对 §五 方案 A 成立，但**不等于一定能配上**——实际以提交页面提示为准。

方案 B 的中转域名是**境内服务器域名**，必须备案，否则填不进去：

| 步骤 | 说明 |
| --- | --- |
| 买域名 | 境内注册商（腾讯云 / 阿里云） |
| 买服务器 | 境内轻量应用服务器，2 核 2G 够用 |
| 提交备案 | 主体证件 + 网站负责人核验 |
| 等待 | 7–20 个工作日 |
| 生效 | 通过后 24 小时才能填进小程序后台 |
| 配证书 | TLS 1.2+，域名与证书完全一致，iOS 不接受自签名 |

## 七、开发阶段先跑通

微信开发者工具：**详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**

此时可直连 `api.audius.co` 验证 UI 与播放链路。代码里 `audius.js` 的 BASE 默认就是直连，不需要改。

> 三个限制：
> 1. 只对**开发者工具**和**手机调试模式**生效，正式版一律校验
> 2. 连 `<image>` 网络图也会绕过校验 → 造成「工具里封面正常、真机白屏」的误判
> 3. 不要用这个状态提审

## 九、报错速查

| 报错 / 现象 | 根因 | 解决 |
| --- | --- | --- |
| `url not in domain list` | 域名没配 / 配错类目 / 没重新编译 | 配 `https://api.audius.co`，重新编译 |
| 不在以下 request 合法域名列表中 | 同上 | 同上 |
| 数据正常、**封面全白** | 封面在随机第三方节点上 | 已知限制，或走 §五 方案 B 的图片代理 |
| 播放没声音、无报错 | 音频域名未配 | 补 `https://creatornode.audius.co` |
| 播放返回空 | 中转层跟随了 302 | 改 `redirect: 'manual'` |
| `SSL handshake failed` | 证书链不全 / TLS < 1.2 | `openssl s_client -showcerts` 查链 |
| 工具正常、真机失败 | 「不校验合法域名」只在工具生效 | 关开关重测 |
| 退到后台静音 | 缺后台播放声明 | `manifest.json` 加 `requiredBackgroundModes: ["audio"]`（已加） |
