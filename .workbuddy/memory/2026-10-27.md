## 应用首页入口（pages/index）设计与落地

**需求**：项目下有商城、壁纸两个子项目，需要一个首页作为统一入口；入口当前 2 个但会持续增加，要求大气、配色舒适。

**决策（用户确认）**：深色高级感基调 · 独立 Ardot 设计文件 · 大卡片 + 预留占位形态。

### 设计文件

- 新建 Ardot 文件 `740919646771918`（应用首页入口 · 子项目导航大厅）
- 两屏：`2:1` 默认态（2 大卡片 + 预留位）、`2:78` 扩展态（2×3 网格 + 添加占位）

- 底色 `#0A0D13`；卡片面 `#171C27`；描边 `rgba(255,255,255,0.10)`
- 氛围光晕：靛蓝 `#3D5AFF` / 紫罗兰 `#7C4DFF` / 暖杏 `#FFA45C` 径向弥散
- 文字四级：主 `#FFFFFF` / 次 `#8C93A0` / 弱 `#6E7684` / 版本 `#4A515E`
- 子项目标识色：商城 `#FFD500`（沿用商城品牌色）、壁纸 `#7FA8FF`
- 圆角：主卡 12px / 网格项 10px / 标签 6px
- 字体：Noto Sans SC + Inter

### 踩坑记录（Ardot）

1. **卡片正文被封面图压住**：卡片 `primaryAxisAlignItems: "SPACE_BETWEEN"` + 子元素 `fill_container` 时宽度计算失效，正文溢出到封面图下方。改为 `MIN` + 显式 gap 后正常。
2. **箭头按钮溢出卡片边界**：用 `layoutPositioning: "ABSOLUTE"` + x/y 定位在 flex 父级内，x 是相对父级内边距的坐标而非预期值，26px 按钮被推到卡片外。正确做法是把它移进正文底行用流内布局（`M()` 到新建的底行容器）。
3. **`M()` 带 index 移动不生效**：想调整子节点顺序时 `M(node, parent, index)` 未按预期排序，图标夹在了标题和描述之间。正确做法是把图标 `M()` 进图标底容器内部（先建容器再归位）。
4. **AI 生图 `G()` 异步未完成时截图会显示 "Image Placeholder"**：壁纸封面改用 `GRADIENT_LINEAR` 三色渐变手写实现，比等生图更快更可控。
5. **渐变色的 `GRADIENT_RADIAL` 必须带 `a` 字段**：`{r:1,g:1,b:1,a:0.42}` 少写 `a` 会解析失败（但 `SOLID` 类型只认 r/g/b）。
6. **同名 text 节点批量插入会失败**：`name:"标签文字"` 重复出现导致该 op 被拒，需保证 name 唯一。
7. **节点名前后可读中文，含 `/` `·` 没问题**，但 `·` 在节点名里可能与路径分隔符冲突，建议用「·」而非「/」。
8. **顶层多屏必须显式写 x/y，否则会重叠在 (0,0)**：`locate_available_space` 只会「提示」可用坐标，
   不会自动写进节点。插入时若不带 `x`/`y`，所有顶层 frame 都落在原点互相压盖。
   正确做法：`I()` 时直接带上 `locate_available_space` 返回的坐标；
   已插完则用 `U(nodeId, {x, y})` 补上（本项目第二屏即因此重叠，事后修正为 x=495）。
   校验方式：`batch_read` 指定 `properties:["x","y","absoluteBoundingBox"]` 读顶层节点坐标。

### 项目侧发现

- `npx vite build` 在本项目会失败（`main.js` 用 HBuilderX 条件编译写法，纯 vite 解析不了 `./App`）——**原有问题，与本次改动无关**。校验新页面改用 `@vue/compiler-sfc` 直接编译 SFC（script/template/style 三项均通过）。
- `sass` 的 `@import` 弃用警告与商城 `pages/mall/styles/tokens.scss` 保持一致，属项目既有风格。
