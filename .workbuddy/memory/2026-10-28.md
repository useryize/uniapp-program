## 天气模块 uni-app 编码落地（2026-10-28 上午）

**8 个页面全部实现**，`pages/weather/`：
home/index · city/search · city/manage · detail/hourly · detail/trend · detail/air · detail/indices · explore/radar

**分层**（对齐商城 mall 模块约定）：
- `api/` —— http.js（请求+Storage 缓存）/ weather.js（Open-Meteo 适配器）/ radar.js（RainViewer）/ city.js（城市检索）/ index.js（统一出口，默认导出 weatherApi）
- `utils/` —— wmo.js（WMO码→中文+图标）/ units.js（风级·AQI·时间换算）/ indices.js（8项生活指数自算）
- `components/` —— weather-tabbar / weather-nav / weather-chart（canvas 折线图）
- `styles/tokens.scss` —— 设计令牌，19 项已与规范文档逐条核对一致
- `data/cities.js` —— 367 城静态库（adcode+坐标+拼音），构建期生成

**关键实现决策**
1. **城市库存为 .js 而非 .json** —— 小程序端 JSON import 与 Node ESM 行为不一致，统一用 JS 模块兼容两端
2. **图标用 PNG 而非内联 SVG** —— 小程序 `<image>` 对 SVG 支持不稳定；11 天气 + 11 深底变体 + 8 指数图标 = 30 个（static/weather/icons/）
3. **用静态 import 而非 require 加载城市库** —— 小程序端 require 运行时不参与打包，require 会导致 city.js 产物只有 1.4KB（数据丢失）
4. **页面不直接请求接口、不计算派生值** —— 风级/AQI分级/生活指数全在适配层完成
5. **折线图轴标签由图表组件自行渲染** —— 与数据点同坐标计算，避免刻度与节点错位

**踩过的坑（已修）**
- CO 污染物单位口径：国标限值 4 mg/m³，接口返回 μg/m³（实测 285），限值表须用 4000 μg/m³，否则永远「超标」
- `is_day` 字段接口本就提供（按真实日出日落），原先用「前 14 小时算白天」的近似是错的
- 霾判定时直接改写 `cur.weather_code` 会污染缓存对象，须用局部变量承接
- 平行数组（hourly.time vs temperature_2m）需防御性访问，防长度不一致越界
- 城市库 adcode 数据源是数字，热门城市用 `===` 字符串比较会全部失配（热门城市显示空白）
- `radarHost` 定义在使用之后会触发 TDZ 报错
- `vite.config.js` 里设 `UNI_INPUT_DIR` 太晚（uni CLI 在加载 vite 配置前就解析了目录）→ 必须用 `cross-env UNI_INPUT_DIR=.` 从 npm scripts 注入
- 项目原本缺 `vite.config.js` 且 `@dcloudio/*` 未写入 package.json（靠 HBuilderX 管理），已补齐 devDependencies 使依赖可复现

**构建**：`npm run build:h5` / `npm run build:mp-weixin`，两端均 DONE。

**接入注意**：微信小程序需在公众平台配置 request 合法域名 —— `api.open-meteo.com`、`air-quality-api.open-meteo.com`、`api.rainviewer.com`、`tilecache.rainviewer.com`（雷达瓦片还需 downloadFile 域名）。详见 `pages/weather/docs/接入说明.md`。

## 新增踩坑（Ardot）

- **已有 SVG 帧的 `svg` 属性更新不生效**（`U(node,{svg:...})` 返回 `updated:{}`）→ 必须删掉重建。
- **复制（C）操作的 `descendants` 键必须用「原节点」的子节点 ID**，用拷贝自身的 ID 会报 `Copy descendant not found`；实际更稳的做法是 C 完再 `batch_read` 拿新 ID 逐个 U。
- **`layout:"none"` 父级内的 SVG 帧绝对定位会偏移**，SVG 框跑出父级 → 改用 flex 流式布局（`layout:"none"` 的父级只留给纯装饰的绝对定位元素）。
- **文字节点设 `width:"hug_contents"` 前必须清掉旧的固定 width**，否则在 flex 里会残留居中/占位行为。
- **横排 7 列日期预报**：列容器必须显式 `height:"hug_contents"` 且父级也要，否则温度文本被裁掉（父 hug 但列 FIXED 时裁切）。
- **图标库内的 reusable 组件被 `I(parent,{type:"ref",ref:...})` 引用后**，想换图标要 `U(instance,{mainComponent:"新组件ID"})`，直接改 svg 不行。
- ⚠️ **删除容器 frame 会递归删除其 reusable 子组件**，导致所有引用该组件的实例的 `mainComponent` 悬空（渲染当时仍正常，但文件重开有风险）。补救：`fetch_component_lib` 查现存组件 → 重建缺失组件 → `U(instance,{mainComponent:"新ID"})` 批量重挂。**改容器结构前先把 reusable 子组件移到别处，或直接新建容器再 M 迁移，不要 D 掉容器。**

## 免费天气接口选型调研（2026-10-28，全部实测）

文档落地：`pages/weather/docs/接口选型方案.md`

**结论**：Open-Meteo（免 Key，1万次/天，非商业）+ RainViewer（雷达瓦片，免 Key）+ 本地城市库（china-area-data，MIT）可覆盖 8 个页面。

**实测结论（关键）**
- Open-Meteo forecast/air-quality/geocoding 三接口均 HTTP 200，字段与设计稿一一对应；16 天预报满足 15 天趋势页
- **Open-Meteo 无生活指数** → 8 项指数需自算（温湿度/降水/UV 阈值推导），或用彩云免费版的 4 项（穿衣/洗车/感冒/紫外线）
- **Open-Meteo 地理编码对中文有歧义**：搜"杭州"会返回四川甘孜同名地 → 必须用本地城市库
- RainViewer `weather-maps.json` → HTTP 200，13 帧 past（10 分钟间隔，实测时间戳与设计稿时间轴刻度吻合），瓦片 PNG HTTP 200；**但 nowcast 数组实测为空**，需优雅降级
- 商业授权是硬门槛：Open-Meteo/RainViewer 免费层均不允许商用，上线运营需换和风/彩云
- wttr.in 实测可用但只有 3 天/无 AQI/无生活指数，仅作降级兜底

**新增设计资产**：图标库补 2 个组件 —— 雷暴(5:6)、冻雨(5:11)，现共 11 个（WMO 码全覆盖）

## 微信合法域名配置指引（2026-10-28 下午）

新增文档 `pages/weather/docs/微信域名配置.md` —— 后台直达地址、填写格式、备案口径、报错速查。

**最终域名清单**：
- request 合法域名：`https://api.open-meteo.com` / `https://air-quality-api.open-meteo.com` / `https://api.rainviewer.com`
- downloadFile 合法域名：`https://tilecache.rainviewer.com`

**关键结论（易踩坑）**：
- 雷达瓦片走 `<image>` → 底层是 `wx.downloadFile`，**不走 request 白名单**，必须单独配 downloadFile；
  开发者工具勾「不校验合法域名」时图片会绕过校验，导致「工具正常、真机白屏」的误判
- 官方「不支持配置父域名，必须用子域名」→ `api.` 与 `air-quality-api.` 两个子域名要分开填
- 域名格式：必须带 `https://`，不能带路径/端口/IP
- 每类上限 200 个；保存后 5–15 分钟才全局生效，需重新编译
- 境外域名（open-meteo / rainviewer 在境外）**不强制 ICP 备案**（微信官方口径：境外主体免备案），
  但审核时以页面提示为准 → 文档给了自建反代兜底方案（`api/http.js` 加 BASE_URL 前缀）
- 四域名实测：HTTP 200 + TLSv1.3 + 证书链完整，满足微信要求
