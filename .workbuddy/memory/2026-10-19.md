## 2026-10-22 修复：商品卡两列宽度错位

- 根因：微信低版本基础库不支持 flex `gap`，卡片宽度 `calc((100% - 20rpx)/2)` 依赖 gap 存在 → 间距丢失/宽度错位
- 修复：改用不依赖 gap 的两列写法——卡片 `width: calc(50% - 20rpx); margin: 0 10rpx 20rpx`，容器 padding 0 14rpx（视觉边距 14+10=24rpx）；涉及 goods-card.vue / index.vue / search/index.vue
- 顺手修：detail sku-mask 的 `inset: 0` 简写改为 top/right/bottom/left（同类兼容问题）
- 教训：本项目所有双列/多列布局禁用 flex gap 依赖；calc 混合 % 与 rpx 时用「50% - 固定值 + 自带 margin」模式

## 2026-10-22 二次修复：商品卡宽度真正的根因

- 上一次只修了 flex gap，用户反馈仍有问题 → 真根因：uniapp 编译微信小程序后 `<goods-card>` 生成自定义宿主节点，flex 子项是宿主而非组件内 view，写在组件内 view 上的 width/margin 全部失效
- 修复：宽度控制权上移——组件根 view 只保留外观（width:100%），页面给组件加 class="goods-cell"（scoped 样式可作用于宿主节点），.goods-cell { display:block; width:341rpx; margin-bottom:20rpx }
- 网格改 justify-content: space-between + 固定 rpx：750-48(边距)-20(列距)=682，每卡 341rpx，摆脱 calc 精度问题
- 教训（项目铁律）：uniapp 小程序端自定义组件用于 flex/grid 时，尺寸样式必须加在组件标签 class 上（或组件开 virtualHost），不能写进组件根 view
