## Ardot 平台新踩坑

11. **遮罩层不渲染**：`layout:"none"` 的空 frame（无子节点）即便给了 fill，
    在导出 PNG/PDF 时也不绘制填充；改用 `type:"rectangle"` 同样不生效。
    结论：需要半透明遮罩呈现时，不要依赖绘制，改为调整背景页本身的视觉。
12. **批量导出**：`export_nodes` 的 PDF 会按画布 top-to-bottom、left-to-right 排序合并
    传入的所有 Frame；PNG 建议每组 ≤5 个节点、scale 2 导出。下载链接有时效性，
    需立即 curl 落地。
13. **padding 会静默丢失**：对同一节点多次 U() 时，后一次若未带上 padding 字段，
    之前设置的 padding 会被重置为 0（表现为文字贴边）。修复时必须把 width/height
    和 padding 一次性写全。
14. **ABSOLUTE 定位也会被重置**：详情页底部操作栏曾设 `layoutPositioning:"ABSOLUTE"`
    y=740，后续批次 U() 该节点未带此字段，被重置回 AUTO 排进内容流滚出屏幕。
    固定吸底元素每次改动都要显式重设 ABSOLUTE + x/y。
15. **横向 flex 里子项写死宽度会互相挤出**：分类页商品网格子卡 128px × 2 列 + gap 10
    = 266 > 可用 263，第二列被裁。窄栏多列布局子项宽度 = (可用宽 − gap×(n−1)) / n
    再留 3~5px 余量。

## 第五轮：导出素材 + 发现 TEXT 节点不支持 padding

用户要求「导出素材」→ 全量导出 17 张 PNG(2x) + PDF，下载覆盖 `pages/mall/design/screens/`。

导出后读本地 PNG 复查（**读本地文件不消耗导出额度，比截图更省**），发现详情页
商品标题与卖点描述仍贴左边缘 —— 追出根因：

18. **TEXT 节点不支持 padding**：`padding` 是 frame 的布局属性，给 `type:"text"` 节点设
   `paddingLeft` 会被静默忽略（U 返回值里也不显示）。之前多轮「补回 16px 边距」全部无效。
   **正确做法**：用带 `paddingLeft/Right` 的 frame 容器包住文本，再把文本 M 进容器。
   影响节点：详情页标题/描述、SKU 弹层背景标题。
   注意：这类贴边问题 `capture_layout` 检测不出来（文字仍在父级宽度内），
   只能靠读导出图/截图肉眼确认。

复查结论：购物车、订单列表、发售日历、支付页等其余页面无贴边问题，无需改动。

最终交付：`screens/` 17 张 PNG（750×1624）+ 17 页 PDF（375×812），共 8.3M。

### 发现的关键偏差（此前实现偏离设计稿之处）

1. **页面区块被加了描边**：设计稿的页面级区块（.panel/.card/.goods-block）是**通栏无边框**，
   靠背景色与留白分段；2px 黑描边只用在**交互元素**（按钮/商品卡/输入框/选项/订单卡）。
   原实现给每个区块都加了框 → 视觉过重。
2. **Hero 结构错**：设计稿是「图片 + 图下独立黑底文案区」两段；原实现把标题叠在图片上。
3. **商品卡角标位置错**：设计稿角标在**图下独立一行**；原实现绝对定位叠在图左上角。
4. **首页入口区只有 3 格**：设计稿是 2×2 四格（发售日历/尺码助手/联名专区/全部商品）。
5. **详情页底部按钮横排**：设计稿是竖排（规格条 + 加购全宽 + 购买全宽），无客服/购物车图标
   （它们在顶部导航栏）。
6. **分类页类目栏**：设计稿是白底 + 选中黑块 + **无分隔线**；原实现浅灰底 + 分隔线。
7. **个人中心**：设计稿面板无框且两块连续；功能宫格 **4 列**；「设置」是太阳图标、
   「尺码档案」是滑块图标；发售提醒在功能宫格**之后**。
8. **尺码助手**：引导语在白底区（不在黑底头部）；推荐卡需含「查看完整尺码表 >」入口。
9. 零散：硬编码色值 `#E8E8E8`/`#FFE9E9`、文案里的 emoji `✓`。
